# Termux runtime reference

## Filesystem and environment

- Termux uses an application-private prefix exposed as `$PREFIX`; its executable directory is `$PREFIX/bin`.
- The default home is exposed as `$HOME` and is not a normal `/home/<user>` directory.
- Android applications normally cannot write to system FHS locations. Avoid `/bin`, `/usr/bin`, `/usr/local/bin`, `/etc`, and `/var` assumptions.
- Termux places its own command directories on `PATH`; use command lookup rather than absolute Linux paths.

## Packages and binaries

- Install compatible command-line dependencies with `pkg`, for example `pkg install git ripgrep`.
- Generic prebuilt Linux binaries may assume glibc, a Linux dynamic loader, or FHS paths unavailable in Termux.
- A pure-Go Android ARM64 build is preferable to silently reusing a Linux artifact. Keep `CGO_ENABLED=0` unless Android linking is intentionally configured and tested.

## Shell and subprocesses

- Resolve `bash` or `sh` from `PATH`.
- Do not invoke `/bin/sh` directly.
- Do not assume `sudo` or system services are available.
- Commands should remain non-interactive unless the user explicitly initiated an interactive operation.

## Storage

- Project files inside `$HOME` have normal Termux access.
- Shared Android storage requires user-granted access and has filesystem limitations. Do not move configuration there automatically.
- Keep application configuration under the user's home, such as `$HOME/.li`.

## Terminal behavior

- Expect small dimensions and frequent resize events.
- Hardware shortcuts may be generated by an extra-keys row or software keyboard and can differ from desktop PTYs.
- Keep explicit alternatives for actions that are difficult to type on mobile.
